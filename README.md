# QuakeWatchBaikal — Геоинформационная аналитическая система мониторинга сейсмичности Байкальской рифтовой зоны

**QuakeWatchBaikal** — веб-платформа для пространственно-временного анализа землетрясений, активных разломов, 3-компонентной поляризации сейсмических волн, лунно-солнечных приливов, нодальных плоскостей и сейсмо-метеорологических данных (ветровых нагрузок).

---

## 1. Программный стек

| Слой системы | Технологии и библиотеки | Назначение |
| :--- | :--- | :--- |
| **Frontend (Клиент)** | **Vue 3** (Composition API), **TypeScript**, **Vite**, **Pinia**, **Vue Router** | Одностраничное веб-приложение (SPA), реактивное управление состоянием и маршрутизация. |
| **UI и визуализация** | **Element Plus**, **Leaflet**, **Plotly.js** | Компоненты интерфейса, интерактивная карта Байкальской рифтовой зоны, многопанельные научные графики. |
| **Веб-сервер / Прокси** | **Nginx** (Alpine) | Раздача скомпилированной статики Vue и обратное проксирование запросов `/api/` на бэкенд. |
| **Backend (Сервер)** | **Python 3.11**, **FastAPI**, **Uvicorn**, **Pydantic v2** | Асинхронный REST API, валидация параметров, управление научными расчетами. |
| **Научное ядро** | **ObsPy**, **NumPy**, **SciPy**, **Pandas**, **PyEphem**, **Matplotlib**, **Shapely** | Чтение `.seed`-сейсмограмм, полосовая фильтрация, метод Гильберта, расчет приливов, спектрограмм, нодальных плоскостей и метеоданных. |
| **База данных (ГИС)** | **PostgreSQL 16** + **PostGIS 3.4**, **SQLAlchemy 2.0 (asyncpg)**, **GeoAlchemy2** | Хранение пользователей, каталогов землетрясений и векторной геометрии активных разломов (`SRID 4326`). |
| **Кэширование** | **Redis 7** | Кэширование результатов тяжелых математических расчетов и сгенерированных графиков в оперативной памяти. |
| **Объектное хранилище** | **RustFS** (S3-совместимое), **Boto3** | Хранение архивов сырых волновых форм (`.seed`) и метеорологических рядов (`.csv`). |
| **Безопасность** | **PyJWT**, **Passlib + Argon2** | Хеширование паролей и защита API-эндпоинтов с помощью Bearer JWT-токенов. |
| **Инфраструктура** | **Docker**, **Docker Compose** | Контейнеризация и оркестрация всех 5 микросервисов системы. |

## 2. Архитектура и принцип работы

Система построена по микросервисной архитектуре и разворачивается в виде **5 изолированных Docker-контейнеров**, объединенных внутренней сетью:

```text
[ Браузер (Vue 3 + Leaflet + Plotly) ]
                 │
                 ▼ (HTTP :3000)
          [ Nginx Proxy ]
           ├──► Статика фронтенда (HTML/JS/CSS)
           └──► /api/v1/* ──► [ FastAPI Backend (:8000) ]
                                     ├──► [ PostgreSQL 16 + PostGIS ] (Пользователи, землетрясения, геометрия разломов)
                                     ├──► [ Redis 7 ]                 (Кэш расчетов поляризации, спектров и графиков)
                                     └──► [ RustFS S3 (:9000) ]       (Бакет quakewatch-data: .seed и MT .csv файлы)
```

### Поток обработки данных:
1. **Точка входа и маршрутизация**: Браузер загружает интерфейс с контейнера `frontend` (Nginx). Все API-запросы к `/api/v1/` проксируются на `backend:8000` (настроен лимит загрузки файлов `100M` и таймаут ожидания расчетов `300s`).
2. **Аутентификация и ГИС-каталоги**:
   * Пользователь регистрируется и входит в систему, получая `JWT`-токен.
   * Каталоги землетрясений (`.csv`) и активных разломов (`.geojson`) загружаются с ПК пользователя через интерфейс, преобразуются в пространственные объекты `LINESTRING` и сохраняются в **PostGIS**.
3. **Научные расчеты и S3-хранилище**:
   * При запуске любого расчетного модуля **FastAPI** сначала проверяет наличие готового результата в **Redis**.
   * Если в кэше пусто, бэкенд через клиент `boto3` обращается к **RustFS (S3)** (бакет `quakewatch-data`), скачивает нужные файлы `SS/ГГГГ/ММ/ДД/*.seed` или `MT/ГГГГ/ММ/*.csv` во временную директорию (при отсутствии в S3 — использует локальный том `/app/data`).
   * **ObsPy, SciPy и PyEphem** выполняют децимацию, фильтрацию, расчет ковариационной матрицы поляризации, лунно-солнечных приливов, спектрограммы и рендер графиков.
   * Результат сохраняется в **Redis** на 1 час и возвращается во фронтенд.

## 4. Запуск и основные адреса

1. **Запуск всех сервисов:**
   ```bash
   docker compose up --build -d
   ```

2. **Доступные интерфейсы:**
   * **Веб-приложение (Vue 3):** `http://localhost:3000`
   * **Документация REST API (Swagger):** `http://localhost:8000/docs`
   * **Веб-консоль S3-хранилища (RustFS):** `http://localhost:9001` (логин: `minioadmin`, пароль: `minioadmin_password`)
